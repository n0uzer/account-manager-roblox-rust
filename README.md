# RbxAccountManager (Rust)

Локальный open-source менеджер аккаунтов Roblox: хранит несколько `.ROBLOSECURITY`,
проверяет их и запускает клиент Roblox под нужным аккаунтом в один клик.

Один бинарник, никакой телеметрии, никаких внешних серверов. Всё лежит на твоём диске.

> ⚠️ **Прочитай перед использованием.** `.ROBLOSECURITY` — это полный доступ к аккаунту,
> включая смену пароля и почты. Кто получил cookie — тот владеет аккаунтом.
> Этот проект не собирает и не отправляет cookie никуда, кроме официального API Roblox,
> но ответственность за файл на диске и за машину, на которой он лежит, — на тебе.

## Скачать

Готовый `rbm.exe` — на странице [Releases](../../releases). Сборка под Windows x64,
запускается без установки и без зависимостей.

Рядом с бинарником лежит `rbm.exe.sha256` — контрольная сумма в формате
`sha256sum` (`<хеш>  rbm.exe`), чтобы можно было проверить скачанное:

```powershell
sha256sum -c rbm.exe.sha256
```

или без утилит:

```powershell
(Get-FileHash .\rbm.exe -Algorithm SHA256).Hash.ToLower() -eq `
    (Get-Content .\rbm.exe.sha256).Split(' ')[0]
```

## Возможности

- Несколько аккаунтов в одном списке: аватарка, название, ник, User ID, заметка.
- Проверка cookie через официальный `users.roblox.com/v1/users/authenticated`.
- Запуск игры под выбранным аккаунтом через deeplink `roblox-player:`.
- **Несколько окон одновременно**: пакетный запуск отмеченных аккаунтов через
  `RobloxPlayerBeta.exe --app`, каждое окно — отдельный клиент Roblox.
- **Приватный сервер по ссылке**: вставляешь ссылку приглашения — менеджер заходит
  именно на него, а не на публичный сервер.
- **Один сервер на всех**: Job ID или «Серверы…» — список публичных серверов игры
  с игроками и пингом, клик подставляет сервер, все аккаунты заходят в него.
- **Раскладка сеткой**: окна сами делят экран (6 окон — 3×2) и ужимаются ниже
  800×600, которые клиент отдавать отказывался.
- **Ограничение нагрузки на окно**: своё разрешение (любые числа), уровень графики,
  текстуры, трава/небо/CSG/сглаживание — чтобы игра не съедала всю видеопамять.
- **Пауза между запусками** в пакете, чтобы шесть клиентов не грузили место разом.
- Вся сеть — в отдельном фоновом потоке: интерфейс не подвисает на проверках и запусках.
- Мастер-пароль: файл хранилища шифруется **Argon2id + AES-256-GCM**.
- Опциональная привязка файла к пользователю Windows через **DPAPI**.
- Автоблокировка по бездействию (выкл / 1 / 5 / 15 / 30 минут) + кнопка «Заблокировать».
- Поиск по названию/нику/заметке/ID и сортировка (по добавлению, названию, нику).
- Экспорт и импорт хранилища в том же шифрованном формате, с нативным выбором файла.
- Аватарки через `thumbnails.roblox.com` с кэшем на диск.
- Копирование cookie в буфер с автоочисткой через 60 секунд (если ты его не заменил).
- Состояние cookie видно в списке: цветная точка у каждого аккаунта + «Проверить все».
- Двойной клик по строке запускает аккаунт, правый клик открывает меню действий.
- Журнал сообщений (кнопка в статус-баре) и итоговая сводка пакетного запуска.
- Place ID можно вставить ссылкой на игру — номер вытащится сам.
- Полностью оффлайн-интерфейс на `egui`/`eframe`.
- **Пресеты**: набор отмеченных аккаунтов + всё из панелей запуска (игра, сервер, режим
  окон, лимиты). Применить, запустить одним нажатием или запускать сам при открытии.
- **Группы и своя игра у аккаунта**: поле «Группа», фильтр по группе, колонка «Группа»;
  у аккаунта можно задать свою игру и сервер — они важнее значений из панели.
- **Массовый импорт cookie**: вставкой, файлом или перетаскиванием файла в окно;
  массовая правка группы/игры/сервера у отмеченных аккаунтов.
- **Проверка cookie при открытии**: после ввода пароля все cookie проверяются сами,
  в журнале одна сводка («вышли: …»).
- **Статус и подробности**: колонка «Статус» (онлайн / в игре / офлайн, раз в минуту,
  выключено по умолчанию), возраст аккаунта, Robux и Premium по кнопке «Детали».
- **Окна под контролем**: автоперезапуск закрывшихся окон, лимит окон, закрытие
  прежнего окна аккаунта при повторном запуске, «Закрыть все окна».
- **К игроку, поиск игры, случайный сервер**: «К игроку…» узнаёт, где играет игрок;
  «Найти игру…» ищет по названию; «Случайный» в списке серверов берёт любой не полный.
- **Резервные копии** `accounts.dat` (последние 5, зашифрованы тем же паролем).
- **Светлая тема** и **автозапуск с Windows** (меню «Настройки»).
- **Анти-AFK** (по желанию, выключен по умолчанию): раз в несколько минут лёгкий ввод
  в окна клиента, чтобы за простой не выкидывало. Окна на миг выходят вперёд, фокус
  потом возвращается.

## Чего здесь нет и не будет

- Сбор cookie из браузера, из памяти процессов, из чужих файлов.
- Обход 2FA, автологин по логину/паролю, «генерация» аккаунтов.
- Отправка данных на сторонние сервера, аналитика, автообновления.
- Автоматизация игры: кликеры, автофарм, скрипты, обход античита. Единственное
  исключение — **анти-AFK**: он отправляет в окно клиента заведомо безобидный ввод
  (подвижка мыши на пиксель, F15), включается только вручную и описан в разделе про ToS.

## Как это работает

### Хранилище

Файл: `%APPDATA%\RbxAccountManager\accounts.dat`

Формат:

```
"RBM1" | salt[16] | nonce[12] | AES-256-GCM(ciphertext)
```

- Ключ выводится из мастер-пароля через Argon2id (параметры по умолчанию).
- Пароль **нигде не сохраняется**. Забыл пароль — данные не восстановить, это by design.
- С включённой привязкой к Windows (DPAPI) сверху добавляется ещё один слой:
  `"RBMD" | DPAPI(...)` — такой файл не расшифруется даже с паролем на другой машине.
- Внутри шифроблоба лежит JSON:
  `{ schema, accounts: [{ id, label, username, user_id, note, cookie, created_at }] }`.
- Запись атомарная: сначала `accounts.tmp` (с принудительным сбросом на диск),
  потом подмена основного файла.
- При блокировке ключ и cookie затираются в памяти (`zeroize`). Расшифрованный JSON,
  в котором лежат все cookie, затирается сразу после шифрования/разбора.
- Создание нового хранилища никогда не перезаписывает уже существующий файл.
- Настройки (Place ID, ссылка на приватный сервер или Job ID, сортировка,
  автоблокировка, лимиты, раскладка) — отдельный `config.json`, секретов там нет.
  Новые поля (`private_link`, `tile_windows`, `launch_gap_secs`, флаги графики,
  `theme`, `max_windows`, `anti_afk` и другие) читаются со значениями по умолчанию,
  так что старый файл продолжает работать. Старый `accounts.dat` без групп и своих
  игр у аккаунтов открывается так же.
- Пресеты — отдельный `presets.json` (названия, id аккаунтов, настройки запуска).
  Cookie в нём нет.
- Резервные копии лежат в `backups\accounts-<время>.dat` рядом с хранилищем: это
  побайтовая копия файла до перезаписи, то есть она зашифрована тем же паролем (и
  привязкой DPAPI, если она включена). Новая копия делается при открытии и при
  сохранении, но не чаще раза в 10 минут; хранятся последние 5. Восстановить —
  заменить `accounts.dat` нужной копией (кнопка «Папка резервных копий» в меню
  «Настройки»).

### Проверка аккаунта

```
GET https://users.roblox.com/v1/users/authenticated
Cookie: .ROBLOSECURITY=...
```

Возвращает `id`, `name`, `displayName`. При 401/403 cookie считается мёртвым.

### Запуск игры

1. `POST https://auth.roblox.com/v1/authentication-ticket/` с заголовком `X-CSRF-TOKEN`.
   Первый запрос обычно отдаёт `403` и сам токен в `x-csrf-token` — он повторяется один раз.
2. Из ответа берётся `rbx-authentication-ticket`.
3. Дальше два режима:
   - **одно окно** (галочка «Несколько окон» снята) — собирается deeplink
     `roblox-player:1+launchmode:play+gameinfo:<ticket>+...` и открывается системным
     обработчиком протокола. Второй клиент Roblox уже не запустится;
   - **несколько окон** (галочка стоит, по умолчанию) — запускается
     `RobloxPlayerBeta.exe --app -t <ticket> -j <join url>`, а менеджер заранее
     занимает имена singleton-защиты клиента (см. ниже). Каждый запуск даёт новое окно.

Клиент Roblox должен быть установлен. Аккаунт, под которым ты залогинен в браузере,
на запуск не влияет — тикет привязан к конкретной cookie.

### Приватный сервер

Поле **«Приватный»** рядом с Place ID принимает ссылку целиком, в двух видах:

```
https://www.roblox.com/games/1234/Name?privateServerLinkCode=ABC123
https://www.roblox.com/share?code=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx&type=Server
```

- Первый вид менеджер разбирает сам: из ссылки берутся и Place ID, и код сервера,
  поэтому поле Place ID можно оставить пустым.
- Второй вид (кнопка «Поделиться» в Roblox) не содержит Place ID. Его менеджер
  разбирает через `POST apis.roblox.com/sharelinks/v1/resolve-link` **при запуске**,
  от имени того же аккаунта, который заходит: эндпоинт требует авторизации, и
  первый запрос Roblox отдаёт `403` с токеном `x-csrf-token`, после чего запрос
  повторяется.
- Ссылку можно вставить и в поле Place ID — менеджер поймёт её и там.
- Пустое поле — обычный публичный сервер. Крестик рядом очищает поле.

Дальше запуск обычный: в режиме нескольких окон собирается
`PlaceLauncher.ashx?request=RequestPrivateGame&placeId=…&privateServerLinkCode=…`,
в режиме одного окна тот же URL уходит в `placelauncherurl:` deeplink'а.

### Конкретный сервер (Job ID) и список серверов

Поле **«Приватный»** принимает не только приватные ссылки, но и **Job ID** — id
публичного сервера. Это то, что нужно, чтобы 5–6 аккаунтов оказались в одном
сервере, а не разъехались по разным матчам.

```
d1e7b1e3-129e-404f-8882-d29d26c72dcd
https://www.roblox.com/games/1818/Name?gameId=d1e7b1e3-129e-404f-8882-d29d26c72dcd
```

- Job ID — 36 символов с дефисами; нижний регистр не обязателен.
- Ссылка с `?gameId=` разбирается сама, Place ID из неё тоже берётся.
- Приоритет: приватный сервер важнее Job ID (если в поле как-то оказалось и то,
  и другое).
- Для запуска собирается
  `PlaceLauncher.ashx?request=RequestGameJob&placeId=…&gameId=…`.

Кнопка **«Серверы…»** рядом с полем открывает список публичных серверов игры:

- `GET games.roblox.com/v1/games/<placeId>/servers/Public` — до 100 серверов;
- показывает игроков, пинг и FPS сервера, пустые сверху (туда проще зайти);
- клик по строке подставляет Job ID в поле «Приватный»;
- кнопка «Обновить» перезапрашивает список. Roblox ограничивает частоту
  (HTTP 429), это видно прямо в окне списка.

### Несколько окон: детали

- Сам по себе `--app` в актуальных клиентах уже не спасает: Roblox держит
  singleton-защиту в именованных объектах `ROBLOX_singletonEvent` и
  `ROBLOX_singletonMutex`. Клиент, который находит такое имя занятым, просит
  запущенное окно закрыться и занимает его место — именно поэтому новое окно
  закрывало предыдущее.
- Менеджер занимает оба имени **мьютексами** в своём процессе. Тогда
  `CreateEvent` в клиенте падает с `ERROR_INVALID_HANDLE`, клиент пишет в свой лог
  «cannot create event to secure single process» и продолжает работу без защиты —
  поэтому все окна живут одновременно.
- Имена держатся всё время работы менеджера, так что первый клиент должен
  запускаться после него. Если Roblox был открыт раньше, менеджер предупредит и
  попросит один раз закрыть окна.
- В клиент ничего не внедряется, память не патчится, файлы игры не меняются:
  клиент просто видит занятое имя.
- Путь к клиенту ищется так: реестр
  `HKCU\Software\Classes\roblox-player\shell\open\command` принимается, только если
  там действительно `RobloxPlayerBeta.exe`; иначе берётся самый свежий
  `RobloxPlayerBeta.exe` из `%LOCALAPPDATA%\Roblox\Versions\version-*\`,
  `%LOCALAPPDATA%\Bloxstrap\Versions`, `%LOCALAPPDATA%\Voidstrap\Versions` и
  `%ProgramFiles(x86)%\Roblox\Versions\`.
- Bloxstrap и его форки переписывают обработчик протокола на себя
  (`Bloxstrap.exe -player "%1"`), поэтому такой путь игнорируется: лаунчер не понимает
  аргументы плеера и открывает своё меню вместо игры. Настоящий клиент лежит в папке
  `Versions` рядом с лаунчером и запускается напрямую.
- Пакетный запуск идёт из очереди: один аккаунт за тик с паузой **1.5 с**,
  чтобы Roblox не посчитал пачку тикетов подозрительной активностью.
- Порядок — как аккаунты отмечены галочками в колонке «Окно».
- Если клиент обновился во время работы — просто сними/поставь галочку и запусти снова,
  путь пересчитывается при каждом запуске.
- Винда не даёт одному и тому же аккаунту два окна в одной игре: второе окно
  выкинет первое. Для разных окон нужны разные аккаунты.
- Все запросы (тикеты, проверка cookie, аватарки) идут в одном фоновом потоке,
  поэтому интерфейс остаётся живым: в статус-баре видно «в работе: N».

### Ограничение FPS, графики, текстур и разрешения

Задача — держать несколько окон открытыми, не выжирая память и процессор.

Все поля ввода принимают **любые числа**: значение набирается прямо в поле (или
тянется мышью), пресетов больше нет. Ноль везде означает «не трогать».

- **FPS** — любое число, по умолчанию выключено (0). Пишется в **настройки самого
  клиента**: `%LOCALAPPDATA%\Roblox\GlobalBasicSettings_13.xml`, поле
  `<int name="FramerateCap">`. Это та же настройка, что в меню игры, поэтому клиент
  её применяет.
- **Графика** (`по умолчанию` / уровни 1–10) — `DFIntDebugFRMQualityLevelOverride`
  в `ClientAppSettings.json`. 1 — самый низкий, 10 — максимальный.
- **Текстуры** (`по умолчанию` / минимум / низкие / средние / высокие) — пара
  `DFFlagTextureQualityOverrideEnabled` + `DFIntTextureQualityOverride` (уровни 0–3).
  Самый сильный рычаг по памяти: меньше текстуры — меньше ОЗУ и видеопамяти на окно.
- **Разрешение окна** — ширина и высота клиентской области в пикселях. Пишется в
  `<Vector2 name="StartScreenSize">` и дополнительно удерживается после запуска.
  0 в любом из полей — размер окна по умолчанию. Не используется, пока включена
  «Раскладка сеткой» (она включена по умолчанию, поля при этом серые). Размер можно
  задать и меньше 800×600. Кнопка **«применить сейчас»** ставит его уже открытым окнам
  и пишет в журнал, какой размер получился у каждого: если клиент вернул свой, это видно
  сразу.
- **Ещё графика** — меню с остальными флагами из белого списка клиента, все по
  умолчанию выключены:
  - **Без травы** — `FIntFRMMinGrassDistance` и `FIntFRMMaxGrassDistance` = 0;
  - **Серое небо** — `FFlagDebugSkyGray`, меньше текстур на окно;
  - **Без вокселизации** — `DFFlagDebugPauseVoxelizer`, замораживает самый
    тяжёлый фоновый пересчёт процессора (тени от солнца перестают двигаться);
  - **Простое CSG** — четыре `DFIntCSGLevelOfDetailSwitchingDistance` = 0;
  - **Сглаживание** — `FIntDebugForceMSAASamples`: `выключено` (1) реально
    снимает нагрузку с видеокарты, `×2/×4/×8` — наоборот.
- **Экономить ОЗУ** — раз в 20 секунд освобождает рабочий набор фоновых окон
  (`EmptyWorkingSet`). Подробности в рецепте ниже.
- **Пауза** — промежуток между запусками в пакете. Шесть клиентов, стартующих
  одновременно, разом грузят процессор, диск и ОЗУ; 2–3 секунды заметно мягче.

#### Раскладка сеткой

Галочка **«Раскладка сеткой»** (включена по умолчанию) раскладывает все окна
клиента по рабочей области экрана: 2 окна — рядом, 4 — 2×2, 6 — 3×2, дальше по
той же логике (сетка подбирается так, чтобы ячейка была ближе к форме монитора).
Позиция и размер пересчитываются после каждого запуска, 45 секунд после последнего
окна сетка удерживается — клиент любит переставить окно во время загрузки места.
Кнопка «разложить сейчас» пересчитывает сетку по уже открытым окнам.

Сетка считается по **всем** окнам `RobloxPlayerBeta.exe`, от старых процессов к
новым: порядок в сетке — порядок запуска. Через 45 секунд окна снова твои.

#### Про минимальный размер окна

Клиент отвечает на `WM_WINDOWPOSCHANGING` своим минимумом — 800×600 клиентской
области (в логе это `dims=800x599`). Именно поэтому раньше окно не сжималось ниже.
Менеджер двигает окно с флагом `SWP_NOSENDCHANGING`: сообщение до клиента не
доходит, окно реально становится меньше, а клиент перерисовывает кадр под новый
размер — в том числе в сетке.

Ограничение осталось только в поле «Разрешение окна»: там значение ниже 800×600
разрешено, но интерфейс игры становится совсем мелким, поэтому для ручного размера
800×600 — разумный минимум. В сетке размер считается сам, и шесть окон на
1920×1080 получают примерно 640×540 каждое.

#### Почему именно эти файлы

Fast-флаги клиент фильтрует своим списком. Проверено одним запуском на живом
клиенте (что отклонено, видно по `Denied local configuration for: …` в его логе):

| Ключ | Результат |
|---|---|
| `DFIntDebugFRMQualityLevelOverride` | принят |
| `DFFlagTextureQualityOverrideEnabled` | принят |
| `DFIntTextureQualityOverride` | принят |
| `FIntFRMMinGrassDistance` / `Max` | приняты |
| `FFlagDebugSkyGray` | принят |
| `DFFlagDebugPauseVoxelizer` | принят |
| `DFIntCSGLevelOfDetailSwitchingDistance*` | приняты |
| `FIntDebugForceMSAASamples` | принят |
| `DFIntTaskSchedulerTargetFps` | отклонён |
| `DFIntFRMConstantFrameTimeTargetMs` | отклонён |
| все ключи DRS и масштаба рендера | отклонены |
| `FIntDebugFRMOptionalMSAALevelOverride` | отклонён |

То есть внешний FPS-лимит через флаги невозможен, а качество, текстуры и
«косметика» (трава, небо, CSG, сглаживание) — можно.

А `GlobalBasicSettings_13.xml` — это не флаг, а собственные настройки клиента
(`UserGameSettings`), которые пишет само меню игры. Оттуда он берёт:

```xml
<int name="FramerateCap">240</int>
<Vector2 name="StartScreenSize"><X>816</X><Y>638</Y></Vector2>
<bool name="Fullscreen">false</bool>
```

Менеджер правит эти три значения перед каждым запуском (при размере окна полный
экран и «развернуть на весь экран» выключаются, иначе клиентской области просто
нет).

Файл принадлежит пользователю Windows, а не аккаунту: все окна получат одинаковые
FPS и размер. Клиент перезаписывает его при выходе, поэтому значения пишутся заново
перед каждым запуском.

Как это работает:

- FPS и размер окна пишутся в `%LOCALAPPDATA%\Roblox\GlobalBasicSettings_13.xml`
  (поле `FramerateCap` и `StartScreenSize`). Клиент читает этот файл при старте и
  перезаписывает при выходе, поэтому значения пишутся заново перед каждым запуском.
- Качество попадает в файл `ClientSettings\ClientAppSettings.json` внутри папки
  версии клиента (`...\Versions\version-<hash>\`), где бы эта папка ни лежала —
  в `Roblox` или рядом с Bloxstrap. Чужие ключи в нём сохраняются, наши значения
  пишутся строками — так их ждёт клиент (и так же их пишет Bloxstrap).
  Обновление Roblox заменяет папку версии, поэтому после апдейта запусти игру из
  менеджера ещё раз — файл перезапишется. Если папка недоступна для записи
  (Roblox в `Program Files`), запуск всё равно произойдёт, а в статусе будет
  предупреждение.
- Ноль в поле ничего не меняет: остаётся то, что стоит в настройках клиента.
- Размер из файла — это стартовый размер окна. Дополнительно он удерживается через
  Win32 (`SetWindowPos` + `AdjustWindowRectEx`): первое окно клиента — маленькая
  плашка логина (около 383×127), а настоящее окно игры клиент создаёт уже после
  загрузки места. Поэтому 90 секунд после запуска поток раз в 0.4 с проверяет окна
  **всех клиентских процессов, запущенных после менеджера**, и поправляет те, что
  отличаются от заданного размера: клиент умеет передавать окно игры новому
  процессу, и одного PID из `--app` для этого мало. После 90 секунд окно снова
  полностью твоё.
- Если окно было в полном экране, менеджер выключает `Fullscreen` и
  `StartMaximized`: у окна без рамки нет клиентской области, которую можно задать.
- В режиме одного окна (deeplink) FPS и размер всё равно применятся: они лежат в
  общих настройках клиента. Неактивны только поля в интерфейсе, потому что
  удерживать размер окна, которое запустил системный обработчик протокола, мы не
  можем.
- FPS и размер общие для пользователя Windows, качество и текстуры — для версии
  клиента.

#### Рецепт для 5–6 окон

1. «Несколько окон» включено, отметь 5–6 **разных** аккаунтов.
2. «Раскладка сеткой» включена — размер окон посчитается сам (для шести на
   1920×1080 это 3×2 примерно по 640×540).
3. Графика: `уровень 1`.
4. Текстуры: `минимум` (если хочется совсем мало памяти) или `низкие`.
5. FPS: `30` (или `20` для совсем слабой машины).
6. «Ещё графика»: **Без травы**, **Серое небо**, **Простое CSG**, **Сглаживание:
   выключено**. На уличных картах это самая заметная разница.
7. Пауза между окнами: `2`–`3` секунды, чтобы шесть клиентов не грузили место
   одновременно.
8. Запускай пакетом. Тикеты запрашиваются по одному, поэтому лимиты не ловятся.

**Про ОЗУ.** Задать клиенту предел памяти снаружи нельзя: job-объект с лимитом
памяти не ограничивает, а убивает процесс при первом же превышении, то есть окно
просто закроется. Поэтому памяти не «кап», а четыре работающих рычага:

- **Текстуры: минимум** — меньше текстур загружается и держится;
- **Графика: уровень 1** — меньше эффектов, теней и моделей;
- **Ещё графика** — без травы, без CSG-деталей, серое небо: меньше геометрии и
  текстур на кадр, а значит и меньше видеопамяти;
- галочка **«Экономить ОЗУ»** — раз в 20 секунд менеджер отдаёт системе рабочий
  набор фоновых окон (`EmptyWorkingSet`). Окно в фокусе не трогается, процессы не
  закрываются: страницы уходят в подкачку и возвращаются по мере надобности.
  Кнопка «сейчас» делает то же по требованию. Замер на живом клиенте:
  `160 МБ -> 4 МБ` у простаивающего окна.

Для 6 окон ориентир — 8 ГБ ОЗУ и 4 ГБ видеопамяти; с текстурами «минимум» и
включённой экономией запас заметно больше.

### Пресеты

Меню «Пресеты → Управление пресетами…». Пресет помнит **отмеченные галочками
аккаунты** и всё, что стоит в панелях запуска: Place ID, приватный сервер или Job ID,
режим окон, паузу, лимит окон, FPS/графику/текстуры, размер окна, раскладку.

- «Применить» отмечает аккаунты и подставляет настройки, ничего не запуская.
- «Запустить» делает то же и сразу запускает отмеченных пакетом.
- «Обновить» перезаписывает пресет текущими отметками и настройками.
- Галочка **«при открытии»** (только у одного пресета): после ввода пароля пресет
  запускается сам. Если в нём не осталось живых аккаунтов, менеджер скажет об этом.
- Удалённые аккаунты из пресета пропускаются, порядок остальных сохраняется.

### Группы, своя игра и сервер у аккаунта

В форме аккаунта есть три необязательных поля: **Группа**, **Игра этого аккаунта**
и **Сервер этого аккаунта** (ссылка на приватный сервер или Job ID).

- Своя игра и свой сервер важнее значений из панели запуска. Аккаунт со своей игрой,
  но без своего сервера **не** берёт сервер из панели: тот сервер принадлежит другой
  игре.
- Имя такого аккаунта в списке подкрашено; без игры в панели и без своей игры запуск
  недоступен.
- Колонка «Группа» появляется, когда хотя бы у одного аккаунта она задана; фильтр
  «Группа:» в строке списка скрывает остальные, поиск ищет и по группе.
- «Изменить отмеченные (N)» задаёт группу, игру или сервер сразу всем отмеченным:
  меняются только те поля, у которых стоит галочка (пустое значение с галочкой
  очищает поле).

### Массовый импорт cookie

«Импорт cookie…» (или перетащи текстовый файл в окно менеджера):

- по одному cookie на строку; можно `название<Tab>cookie`, `название,cookie` или
  `название;cookie`. Префикс `.ROBLOSECURITY=` и кавычки убираются;
- до добавления видно, сколько строк разобрано, сколько повторов и что пропущено и
  почему; cookie, которые уже есть в менеджере, не добавляются второй раз;
- можно сразу задать группу и проверить новые cookie после добавления;
- читаются UTF-8 (с BOM или без) и UTF-16 из Блокнота; бинарные файлы и файлы больше
  2 МБ отклоняются. Текст с cookie затирается в памяти при закрытии окна.

### Статус, детали аккаунта, поиск игры и игрока

Всё это — только чтение через публичные эндпоинты Roblox, отвечающие на запросы от
имени одного из твоих аккаунтов (выбранного, а если он мёртв — первого рабочего).
Формат ответов Roblox менялся не раз, поэтому разбор терпимый, а при сбое менеджер
показывает ошибку, а не падает.

- **Проверка при открытии** (меню «Настройки», включена по умолчанию): по одному
  запросу на аккаунт после ввода пароля.
- **«Показывать, кто в игре»** (выключено по умолчанию): один запрос раз в минуту ко
  всем аккаунтам сразу; после ошибки следующая попытка через 5 минут.
- **«Детали»** в нижней панели: возраст аккаунта, баланс Robux, Premium.
- **«Найти игру…»**: поиск по названию, клик по игре подставляет её Place ID.
- **«К игроку…»**: ник, ссылка на профиль или ID; если Roblox показывает, где игрок
  играет, в панель подставляются игра и сервер.
- **«Случайный»** в окне «Серверы игры»: любой сервер, где ещё есть места.

### Окна под контролем

Меню «Окна» и кнопка «Закрыть все окна» в панели запуска.

- Менеджер сопоставляет окна с аккаунтами по порядку запуска и времени создания
  процесса клиента, поэтому знает, какое окно чьё. Передачу игры новому процессу
  клиента он отличает от потери окна (льготные 60 секунд).
- **Перезапускать закрывшиеся окна**: если окно пропало, а закрывал его не ты через
  менеджер, аккаунт запускается снова, не больше 3 раз за 10 минут. Работает, пока
  хранилище открыто: после блокировки cookie недоступны. Закрыл окно вручную и не
  хочешь, чтобы оно вернулось — выключи опцию или закрой окно из меню аккаунта
  («Закрыть окно»).
- **Закрывать прежнее окно при повторном запуске**: один аккаунт не сидит в игре в
  двух окнах, второй вход выкидывает первый. Закрывается только окно, открытое
  менеджером.
- **Лимит окон**: пакет ждёт свободного места, а не открывает лишние (0 — без лимита).
- **Закрыть все окна** закрывает *все* клиенты Roblox, в том числе запущенные не из
  менеджера, и просит второго нажатия в течение 5 секунд.

### Анти-AFK

Меню «Окна → Анти-AFK», выключен по умолчанию. Roblox выкидывает игрока примерно
через 20 минут без ввода, поэтому интервал ограничен 1–19 минутами (по умолчанию 10).
Раз в интервал в каждое окно клиента отправляется лёгкий ввод: сдвиг мыши на пиксель и
обратно и нажатие F15 — клавиши, которую игры ни на что не вешают. Режимов два:

- **Надёжный** (по умолчанию). Окно на долю секунды выходит вперёд, получает настоящий
  ввод (`SendInput`), и фокус возвращается на прежнее окно. Для клиента это то же, что
  человек за клавиатурой, поэтому работает независимо от версии клиента. Цена — короткое
  мигание окон. Перед этим менеджер до 5 секунд ждёт, пока ты перестанешь печатать и
  двигать мышь, чтобы не отобрать фокус на середине слова. Свёрнутое окно на миг
  разворачивается и сворачивается обратно.
- **Тихий**. Те же события кладутся прямо в окно (`PostMessageW`), фокус не трогается.
  Современные клиенты, как правило, игнорируют ввод, пришедший не как активному окну,
  так что режим оставлен на случай, если у тебя он всё же срабатывает.

В клиент ничего не внедряется, память не патчится. Кнопка «сейчас» запускает один круг, а
каждый круг (и по таймеру тоже) пишет в журнал, в сколько окон ввод дошёл и сколько не
удалось вывести вперёд.

- **Ограничения.** Клиент, запущенный от администратора, игнорирует ввод от менеджера с
  обычными правами (так задумано в Windows): такие окна попадут в «не вышли вперёд».
  Надёжный режим нужен рабочий стол и разблокированный экран.
- Это автоматизация ввода, см. раздел про ToS.

### Автоблокировка

- Порог задаётся в меню «Настройки → Автоблокировка»: выкл / 1 / 5 / 15 / 30 минут
  (по умолчанию 15).
- Любое событие мыши или клавиатуры в окне сбрасывает таймер.
- По истечении хранилище закрывается, ключ и cookie затираются в памяти,
  все незавершённые галочки и очередь запуска сбрасываются.
- Таймер работает по системному времени, окно должно быть запущено. Приложение само
  просыпается к моменту блокировки, даже если вы ничего не трогаете.

### Поиск и сортировка

- Строка поиска фильтрует по названию, нику, группе, заметке и User ID (без учёта
  регистра).
- Сортировка: по добавлению (новые сверху), по названию, по нику.
- Оба параметра сохраняются в `config.json`.

### Аватарки

- Запрашиваются у `thumbnails.roblox.com/v1/users/avatar-headshot` (48×48, png),
  качаются в фоне, максимум 3 запроса одновременно.
- Кэш: `%APPDATA%\RbxAccountManager\avatars\<user_id>.png` — при повторном
  запуске сеть не нужна.
- Пока аватара нет (или он не загрузился), в строке показывается первая буква названия
  в кружке. Неудачная загрузка не повторяется в цикле: новая попытка — после
  следующей разблокировки.

### Экспорт и импорт

- Меню «Файл → Экспорт…» копирует `accounts.dat` как есть: тот же пароль, та же привязка
  к Windows. Поэтому файл с включённым DPAPI на другом ПК бесполезен — это фича, а не баг.
  Кнопка «Обзор…» открывает системный диалог. Экспорт на сам рабочий файл запрещён,
  а перезапись существующего файла требует второго нажатия («Заменить»).
- «Файл → Импорт…» читает другой файл, спрашивает **его** пароль, расшифровывает и
  добавляет аккаунты к текущим. Дубликаты по cookie пропускаются, id перегенерируются.
- Импорт не меняет текущий пароль и не трогает существующие записи.

## Использование

1. Запусти `rbm.exe`.
2. Первый старт: придумай мастер-пароль (минимум 6 символов) и повтори его.
3. `Добавить` → название, `.ROBLOSECURITY`, заметка. Cookie проверяется сразу;
   если не прошёл — аккаунт всё равно можно сохранить (например, у Roblox лежит API).
4. `Place ID` → число из ссылки на игру (`roblox.com/games/1818/Name` → `1818`)
   или сама ссылка целиком — номер вытащится автоматически.
5. Выбери аккаунт в списке и нажми `Запустить «<имя>»` (или просто сделай двойной клик
   по строке) — откроется одно окно.
6. Для нескольких окон: поставь галочки в первой колонке у нужных аккаунтов
   (разные аккаунты!) и нажми `Запустить выбранные (N)`. Галочка в заголовке
   отмечает все показанные аккаунты.

Горячие клавиши: `Enter` в окне пароля и в формах — подтвердить (в формах переходит
к следующему полю), `Esc` — закрыть верхний диалог.

Элементы интерфейса:

| Где | Элемент | Что делает |
|---|---|---|
| Меню «Файл» | Экспорт… / Импорт… | копия хранилища и слияние чужого файла |
| Меню «Файл» | Заблокировать | закрывает хранилище и затирает ключ в памяти (дубль — справа в меню) |
| Меню «Настройки» | Автоблокировка | выкл / 1 / 5 / 15 / 30 минут бездействия |
| Меню «Настройки» | Привязка к Windows (DPAPI) | включает/снимает привязку файла к текущему пользователю |
| Тулбар | Place ID | номер плейса или ссылка на игру, сохраняется в конфиг |

## Безопасность: честный список

Что сделано:

- Файл на диске всегда зашифрован, plaintext-cookie на диск не попадает.
- AEAD: подмена байтов в файле ломает расшифровку (ошибка, а не мусор).
- Argon2id делает перебор мастер-пароля дорогим.
- Буфер обмена очищается через минуту, если его не перезаписали.
- Автоблокировка по бездействию: ключ и cookie затираются в памяти.
- Опциональный DPAPI: файл нельзя расшифровать на другой машине/пользователе.

Чего **не** сделано и почему это важно:

- Мастер-пароль живёт в памяти процесса на время работы. Любой, кто может читать память
  процесса (админ, malware, дебаггер), достанет и пароль, и cookie.
- DPAPI выключен по умолчанию: с ним бэкап файла бесполезен на другом ПК.
- Шифрование не спасает от кейлоггера, который перехватит мастер-пароль при вводе.
- Аватарки кэшируются на диск в открытом виде — это картинки, не секреты.

Если нужен максимум защиты — держи файл на зашифрованном системном диске (BitLocker)
и не храни в менеджере основной аккаунт с ценными предметами.

## Про ToS Roblox и бан

Этот проект использует те же публичные эндпоинты, что и сайт Roblox, ничего не эксплойтит
и не автоматизирует игровой процесс. Исключение — опциональный **анти-AFK**: он
отправляет в окна клиента синтетический ввод, чтобы за простой не выкидывало. Roblox и
отдельные игры могут считать это нарушением правил, поэтому по умолчанию он выключен и
включается только осознанно. Тем не менее:

- Cookie-логин в сторонних клиентах — серая зона. Roblox может расценить аномальные
  входы как подозрительную активность и выдать смену пароля/выход из всех сессий.
- Не запускай десятки аккаунтов одновременно с одного IP — это ловится античитом/фродом.
- Автоперезапуск, статус «кто в игре» и проверка cookie при открытии — это дополнительные
  запросы к Roblox; они ограничены (3 перезапуска за 10 минут, один запрос в минуту),
  но чем их больше, тем заметнее трафик.
- Используй на свой риск. Автор не несёт ответственности за блокировки аккаунтов.

## Тесты и CI

```powershell
cargo test
cargo fmt --all -- --check
cargo clippy --all-targets
```

Юнит-тесты покрывают шифрование (roundtrip, неверный пароль, подмена байтов),
хранилище (создание/переоткрытие, слияние дубликатов, чтение экспорта, длина пароля в
символах, отказ перезаписать существующий файл), разбор Place ID из ссылки,
валидацию аватарок и слияние клиентских настроек (строковые значения, сохранение
чужих ключей, удаление лимитов при нуле, пары ключей текстур), занятие
singleton-имён клиента, поиск клиентских процессов и освобождение памяти
(`EmptyWorkingSet`), разбор ссылок на приватный сервер (оба формата, включая ответ
sharelinks) и Job ID, разбор ответа списка серверов, арифметику сетки окон (6 окон
на 16:9 — это 3×2) и правку настроек игры (`FramerateCap`, `StartScreenSize`,
выключение полного экрана, сохранность чужих полей). Сетевых тестов нет: они
трогали бы живые аккаунты. Новые модули покрыты на примерах ответов Roblox, написанных
вручную: пресеты, разбор списка cookie, резервные копии (ротация и интервал), слежение
за окнами и лимитер перезапусков, разбор ответов статуса, баланса и поиска игр, выбор
назначения для аккаунта. Всего 144 теста; код, который работает только в Windows
(реестр, окна, ввод анти-AFK), на Linux не собирается и тестами не покрыт — его
проверяет только CI на `windows-latest`.

GitHub Actions на `windows-latest` прогоняет fmt, clippy, тесты и release-сборку
на каждый push в `main` и в каждый pull request.

### Выпуск релиза

Релиз собирает и публикует workflow `.github/workflows/release.yml`:

1. Поднять `version` в `Cargo.toml` и закоммитить (`cargo build` заодно обновит
   `Cargo.lock`; без этого сборка с `--locked` не пройдёт).
2. Поставить тег, совпадающий с версией, и отправить его:

   ```powershell
   git tag v0.5.0
   git push origin v0.5.0
   ```

Workflow проверяет, что тег совпадает с версией в `Cargo.toml`, гоняет тесты, собирает
`rbm.exe` (Windows x64) и создаёт релиз с автоописанием из коммитов и pull request'ов.
К релизу прикладываются `rbm.exe` и `rbm.exe.sha256` (формат `sha256sum`, как описано
выше). Тег вида `v0.5.0-rc.1` публикуется как пре-релиз. Повторный запуск для того же
тега заменяет файлы в уже созданном релизе.

Запустить можно и вручную: вкладка Actions → Release → Run workflow, в поле указать
тег; он будет создан на выбранном коммите.
