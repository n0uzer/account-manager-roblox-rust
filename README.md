# RbxAccountManager (Rust)

Локальный open-source менеджер аккаунтов Roblox: хранит несколько `.ROBLOSECURITY`,
проверяет их и запускает клиент Roblox под нужным аккаунтом в один клик.

Один бинарник, никакой телеметрии, никаких внешних серверов. Всё лежит на твоём диске.

> ⚠️ **Прочитай перед использованием.** `.ROBLOSECURITY` — это полный доступ к аккаунту,
> включая смену пароля и почты. Кто получил cookie — тот владеет аккаунтом.
> Этот проект не собирает и не отправляет cookie никуда, кроме официального API Roblox,
> но ответственность за файл на диске и за машину, на которой он лежит, — на тебе.

---

## Возможности

- Несколько аккаунтов в одном списке: название, ник, User ID, заметка.
- Проверка cookie через официальный `users.roblox.com/v1/users/authenticated`.
- Запуск игры под выбранным аккаунтом через deeplink `roblox-player:`.
- **Несколько окон одновременно**: пакетный запуск отмеченных аккаунтов через
  `RobloxPlayerBeta.exe --app`, каждое окно — отдельный клиент Roblox.
- Мастер-пароль: файл хранилища шифруется **Argon2id + AES-256-GCM**.
- Копирование cookie в буфер с автоочисткой через 60 секунд (если ты его не заменил).
- Полностью оффлайн-интерфейс на `egui`/`eframe`.

---

## Чего здесь нет и не будет

- Сбор cookie из браузера, из памяти процессов, из чужих файлов.
- Обход 2FA, автологин по логину/паролю, «генерация» аккаунтов.
- Отправка данных на сторонние сервера, аналитика, автообновления.
- Автоматизация игры: кликеры, автофарм, скрипты, обход античита.

cargo build --release

## Как это работает

### Хранилище

Файл: `%APPDATA%\RbxAccountManager\accounts.dat`

Формат:

```
"RBM1" | salt[16] | nonce[12] | AES-256-GCM(ciphertext)
```

- Ключ выводится из мастер-пароля через Argon2id (параметры по умолчанию).
- Пароль **нигде не сохраняется**. Забыл пароль — данные не восстановить, это by design.
- Внутри шифроблоба лежит JSON: `{ schema, accounts: [{ id, label, username, user_id, note, cookie }] }`.
- Запись атомарная: сначала `accounts.tmp`, потом подмена основного файла.

### Проверка аккаунта

```
GET https://users.roblox.com/v1/users/authenticated
Cookie: .ROBLOSECURITY=...
```

Возвращает `id`, `name`, `displayName`. При 401/403 cookie считается мёртвым.

### Запуск игры

1. `POST https://auth.roblox.com/v1/authentication-ticket/` с заголовком `X-CSRF-TOKEN`.
   Первый запрос обычно отдаёт `403` и сам токен в `x-csrf-token` — он повторяется один раз.
2. Из ответа берётся `rbx-authentication-ticket`.
3. Дальше два режима:
   - **одно окно** (галочка «Несколько окон» снята) — собирается deeplink
     `roblox-player:1+launchmode:play+gameinfo:<ticket>+...` и открывается системным
     обработчиком протокола. Второй клиент Roblox уже не запустится;
   - **несколько окон** (галочка стоит, по умолчанию) — запускается
     `RobloxPlayerBeta.exe --app -t <ticket> -j <join url>`.
     Флаг `--app` обходит проверку единственного экземпляра, поэтому каждый запуск
     даёт новое окно.

Клиент Roblox должен быть установлен. Аккаунт, под которым ты залогинен в браузере,
на запуск не влияет — тикет привязан к конкретной cookie.

### Несколько окон: детали

- Путь к клиенту берётся из реестра
  `HKCU\Software\Classes\roblox-player\shell\open\command`, а если там пусто —
  ищется самый свежий `RobloxPlayerBeta.exe` в
  `%LOCALAPPDATA%\Roblox\Versions\version-*\` и `%ProgramFiles(x86)%\Roblox\Versions\`.
- Пакетный запуск идёт из очереди: один аккаунт за тик с паузой **1.5 с**,
  чтобы Roblox не посчитал пачку тикетов подозрительной активностью.
- Порядок — как аккаунты отмечены галочками в колонке «Окно».
- Если клиент обновился во время работы — просто сними/поставь галочку и запусти снова,
  путь пересчитывается при каждом запуске.
- Винда не даёт одному и тому же аккаунту два окна в одной игре: второе окно
  выкинет первое. Для разных окон нужны разные аккаунты.
- Пакетный запуск выполняется в UI-потоке, поэтому интерфейс «замирает» на время
  получения тикета (~0.3–1 с на аккаунт). Это известное ограничение, см. roadmap.

## Использование

1. Запусти `rbm.exe`.
2. Первый старт: придумай мастер-пароль (минимум 6 символов) и повтори его.
3. `Добавить` → название, `.ROBLOSECURITY`, заметка. Cookie проверяется сразу;
   если не прошёл — аккаунт всё равно можно сохранить (например, у Roblox лежит API).
4. `Place ID` → число из ссылки на игру: `roblox.com/games/**1818**/Name` → `1818`.
5. Выбери аккаунт в списке и нажми `Запустить игру` — откроется одно окно.
6. Для нескольких окон: поставь галочки в колонке «Окно» у нужных аккаунтов
   (разные аккаунты!) и нажми `Запустить выбранные (N)`.

Кнопки:

| Кнопка / элемент | Что делает |
|---|---|
| Запустить игру | тикет + запуск клиента для выделенного аккаунта |
| Запустить выбранные (N) | пакетный запуск всех отмеченных, по одному с паузой |
| Несколько окон (--app) | режим запуска: отдельный процесс клиента на каждое окно |
| Добавить / Изменить | форма аккаунта |
| Проверить cookie | обновляет ник и User ID |
| Cookie → буфер | копирует cookie, автоочистка через 60 с |
| Показать cookie | окно с текстом (только для чтения) |
| Удалить | убирает запись из менеджера, аккаунт Roblox не трогает |

## Безопасность: честный список

Что сделано:

- Файл на диске всегда зашифрован, plaintext-cookie на диск не попадает.
- AEAD: подмена байтов в файле ломает расшифровку (ошибка, а не мусор).
- Argon2id делает перебор мастер-пароля дорогим.
- Буфер обмена очищается через минуту, если его не перезаписали.

Чего **не** сделано и почему это важно:

- Мастер-пароль живёт в памяти процесса на время работы. Любой, кто может читать память
  процесса (админ, malware, дебаггер), достанет и пароль, и cookie.
- Нет привязки к железу/пользователю Windows: файл расшифруется на любой машине,
  если знаешь пароль. Это осознанно — иначе бэкап бесполезен.
- Нет автоблокировки по неактивности. Закрыл окно — хранилище закрыто.
- Шифрование не спасает от кейлоггера, который перехватит мастер-пароль при вводе.

Если нужен максимум защиты — держи файл на зашифрованном системном диске (BitLocker)
и не храни в менеджере основной аккаунт с ценными предметами.

## Про ToS Roblox и бан

Этот проект использует те же публичные эндпоинты, что и сайт Roblox, ничего не эксплойтит
и не автоматизирует игровой процесс. Тем не менее:

- Cookie-логин в сторонних клиентах — серая зона. Roblox может расценить аномальные
  входы как подозрительную активность и выдать смену пароля/выход из всех сессий.
- Не запускай десятки аккаунтов одновременно с одного IP — это ловится античитом/фродом.
- Используй на свой риск. Автор не несёт ответственности за блокировки аккаунтов.
